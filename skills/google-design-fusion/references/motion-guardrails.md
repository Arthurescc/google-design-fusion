# Motion Guardrails

Reject these by default:

- looping motion with no progress or state meaning
- glow, shimmer, bounce, and scale stacked together on one control
- motion on secondary surfaces before the main CTA is clear
- hover-only affordances for critical actions
- delayed transitions that make the interface feel sluggish
- animations that lower contrast or blur important text

For audits, ask:

1. What action or state does this motion explain?
2. Would the design still read clearly if the motion were removed?
3. Does the motion strengthen hierarchy or just add spectacle?
4. Does the motion survive reduced-motion expectations?
